# Paseo Director

由你选择设计、执行和审核 AI：设计 AI 制定总纲，执行 AI 实现，审核 AI 检查并提出返工要求，最后由你验收。审核默认沿用设计 AI，也可单独指定模型和会话。原生 Paseo 0.8 插件，前端使用 React Native，调度运行在 daemon 主机上。

## 使用

1. 进入已有工作区，在 Agent 输入框发送 `/director` 打开面板；也可从工作区命令中心选择 **Director：安排 AI 协作**。
2. 打开 **协作设置**，依次为 **设计 AI → 执行 AI → 审核 AI** 选择供应商和模型。第三步可选「沿用设计 AI 审核」，也可选「单独选择审核 AI」；权限、推理强度和 MCP 在「模型高级设置」。独立审核即使选择相同模型也会新建审核会话，调整审核配置不会联动修改其他角色。更多执行者和类型 / 任务 ID 规则放在第二步。
3. 默认由审核 AI 审核并决定验证方式，无需填写命令。若需要固定执行某些检查，可展开「指定额外检查命令（可选）」，选择项目支持的检查或输入完整命令，例如 `pnpm run typecheck`。每项命令独立执行，支持引号包裹带空格的参数，不支持 `&&`、管道、重定向或变量展开。额外检查在新工作区运行，失败时不能审核通过；已有配置会保留，可点击「移除全部额外检查」取消。
4. 在任一角色页点击底部 **保存设置**，返回新建任务后填写目标，点击 **开始设计与执行**。工作区入口直接使用当前目录；需要切换时展开「执行位置」，选择已有工作区或新建独立工作区。独立工作区需要填写来源 Git 仓库的绝对路径。开始按钮固定在面板底部。
5. 在任务详情查看总纲、实际执行 AI、测试输出、差异文件、审核意见和返工记录。权限请求在对应 Paseo AI 会话处理。
6. AI 最终审核通过后，任务进入 **等待你验收**。「交付成果与验收」先展示变更文件、逐项审核依据、检查输出和代码差异，再提供 **验收通过，完成任务** 与 **提出修改意见**。选择提出修改后填写意见并提交；展开「不采纳此成果」也可结束任务，保留现有文件和分支。暂不决定会持续等待，不会自动采纳。验收只确认成果，合并与推送分支需另外操作。

**按任务分配 AI**：在「协作设置 → 选择执行 AI → 按任务分配不同 AI」添加规则，例如 `frontend` 交给前端 AI、`backend` 交给后端 AI、`tests` 交给测试 AI。可点选常用类型或自定义名称，也可按总纲中的任务 ID 指定。类型名称和任务 ID 都是精确匹配；优先级为具体任务指定 → 类型指定 → 设计 AI 挑选（需开启）→ 默认执行者。需要更多 AI 时，先在「管理其他 AI」添加供应商与模型配置并「应用到 AI 草稿」，再将规则「添加到分配草稿」。最后点击底部「保存设置」统一生效；未完成的 AI、规则和检查编辑会提示先处理。审核角色统一在第三步指定；这里分配的是执行 AI，由 Director 创建或复用对应的协作会话，不接管已有普通聊天。

**前置提示词**：三个角色各有独立输入框，可填写自己的要求或点击「填入参考提示词」。执行提示词用于所有实际执行者，包括按类型或任务 ID 指定的 AI；审核提示词用于任务审核、返工复审和最终审核，沿用设计会话时也使用审核要求。每个 AI 的「模型高级设置」还可填写补充提示词，例如要求前端专家沿用现有组件库、后端专家重点检查接口兼容性。角色要求与实际分配到的 AI 补充要求一起发送，每项最多 8000 个字符，留空不追加要求。每轮交接卡中的「本轮前置提示词」可查看实际发送的内容。这些要求补充内置职责，不改变角色分工、权限、审核门槛或结果格式。保存仅影响新任务；已开始的任务及其返工、追加修改继续使用创建时保存的配置。

任务详情顶部会显示四个阶段、已通过审核的子任务数和当前需要做的操作。等待权限时可直接打开对应 AI 会话；总纲待确认时，默认展开实现方案。检查输出默认收起，失败输出自动展开；「查看代码差异」可直接查看变更文件与差异预览，完整日志和差异文件路径也会保留。运行记录先显示最近 12 条，可继续查看更早记录。

任务记录显示当前主机的任务状态、代码目录、更新时间与子任务进度。创建页会提示缺少的输入和长度限制，提交失败后保留输入，重试同一次请求不会重复创建任务。从任务详情进入设置，保存后返回原任务。不同主机的设置、模型目录和任务缓存互相隔离。

**设置草稿**：编辑内容自动保留在当前主机，显示「草稿已保留」后，关闭面板、刷新或从其他客户端连接同一主机都能恢复；尚未选完的 AI、未添加的检查命令和超出正式设置限制的输入也可作为草稿保留。草稿不用于执行，点击任一角色页底部「保存设置」后才影响新任务，保存成功会清除草稿。可以选择「放弃草稿」并确认后恢复已生效的设置。断线时会提示草稿尚未同步，请保留面板并重试。多个窗口同时编辑会检查版本，较旧的内容不会覆盖新草稿或已生效的设置；遇到冲突可放弃本页修改并读取最新草稿。

提交修改意见无需重写原目标：原设计 AI 会参考原目标、上一版总纲和你的意见，安排执行 AI 在现有成果上修改，再交给原审核 AI 复审，最后再次等待你验收。开启了总纲确认时，修改计划也需要先批准。对应任务 ID 和 AI 配置不变时会复用原执行会话；新任务使用原团队配置。每次用户主动追加修改会获得新一轮调用与时间预算，历史记录保留。旧版本标为完成的 AI 审核结果也可以在详情验收或追加修改，无需重建工作区。

审核 AI 负责每项任务与最终集成的审核。遇到问题由原执行者返工；用户追加需求则交回原设计 AI 调整总纲。三个角色留在同一工作区，任务详情会展示审核模型及「打开审核 AI 会话」。旧配置未指定审核 AI 时继续使用原设计会话，保存新配置只影响之后创建的任务。

保存团队配置后，从左侧工作区列表进入已有工作区，在其中的 Paseo Agent 输入框发送：

```text
/director 为这个项目增加登录功能，并补齐测试
```

**「新建工作区」页面不支持 `/director`。** Paseo 0.8 只在已有工作区内加载插件命令；在新建页面发送它会创建普通 AI 会话。请先进入已有工作区，再发送 `/director` 打开面板并填写目标。可以先输入 `/dir`，确认候选列表出现 `/director` 后再发送。

插件使用当前工作区目录和该主机保存的 AI 分工创建任务，自动打开进度详情。只输入 `/director` 则打开面板。普通聊天不会触发协作；当前聊天框选择的模型不改变已保存的团队分工。命令提交的任务使用独立设计 AI 会话，不自动带入当前聊天历史，请在描述中写明需求。首次未配置团队时，会打开设置并保留任务描述，保存后点击「开始设计与执行」。输入框里有附件时，Paseo 不执行插件斜杠命令；请单独发送命令。若已在普通聊天里发出 `/director`，之后打开 Director 不会接管或转换那次普通聊天。

从已有工作区发送 `/director 任务描述`，默认在当前目录新建并切换到成果分支 `director/<run-id>`。设计、执行和审核会话都归属发起任务的工作区，通过详情中各角色的会话按钮打开对应标签页。当前工作区的其他会话也会看到分支和代码变化；同一目录只允许一个未结束的 Director 任务。开始前请提交或通过 Git stash 保存未提交改动。

工作区 Director 面板默认「在当前工作区执行」。设计、执行和审核会话都留在当前工作区，不额外增加侧栏工作区条目。只有主动选择「新建独立工作区」时，才会创建独立 Git worktree 和侧栏条目。旧任务仍保留原工作区，不迁移已创建的 AI 会话。两种方式都保留成果分支，不自动推送、合并或部署；当前工作区执行期间请保持成果分支，切换后插件会在派发前要求切回。

已有工作区在切换成果分支前会保留原显示名称，用户设置的名称优先；侧栏主标题不会随分支变为 `director/随机编号`。这个分支名仍会显示在 Git 分支信息中。三个角色的会话标题使用任务名称，主动新建的独立工作区也使用目标摘要命名。已经显示成随机编号的旧工作区可手动重命名；再次从该工作区发起任务时，未设置标题的旧 Director 分支名会恢复为项目名。

AI 聊天中的自动交接指令默认显示为中文任务卡，展示本轮职责、目标、分工和下一步；「查看原始指令」可展开完整内容。AI 收到的完整协议不变，已发送的旧指令也支持此显示方式。

运行记录分别显示准备派发、指令送达、AI 开始处理、权限等待和恢复。审核 AI 尚在忙或等待权限时，会明确说明审核指令尚未发送。开启「先让我确认设计总纲」后，总纲生成会暂停；任务顶部和运行记录旁都提供「总纲通过，开始执行」，批准后才会派发执行 AI。

任务审核和最终审核会附带调度器保存的总纲批准、指令派发、结果接收及历史审核记录，供审核 AI 核对流程顺序。旧任务可使用已有运行记录补充证据；没有记录的时间不会推测。因缺少证据受阻时，补齐后重试审核会保留已通过的执行成果，交回原审核 AI 复审。

刷新、重新打开工作区面板或更新插件后，会从已保存的数据恢复该工作区的任务，优先显示未结束任务；等待总纲批准的任务也会直接恢复到确认页面。「任务记录」用于查看已有任务，「新建任务」才会打开空白目标表单。

设计 AI 的总纲、执行 AI 的结果和审核 AI 的回复也会显示为中文卡片，JSON 中的换行正常展开，任务详情可逐项查看。生成过程中逐步展示中文摘要和实现方案，并标记「生成中」，完整回复通过格式校验后自动展示任务和审核详情；「查看原始回复」始终保留完整原文。中断或格式不完整的回复会提示待整理，不会显示为已通过。此展示仅用于 Director 会话，不改变后台调度或审核结论。

## 安装、更新与卸载

本插件位于多插件仓库 [`lalaze/paseo-plugins`](https://github.com/lalaze/paseo-plugins) 的 [`director/`](.) 目录。安装到另一台主机的完整步骤见 [INSTALL.md](./INSTALL.md)。如果只是换电脑连接同一个 Paseo daemon，无需重复安装。

需要 **Paseo daemon 和 app 0.8.x**、**Node.js 22.13+**、Git，以及至少一个已登录并可用的 Paseo AI provider。此次实现基于本机 Paseo **0.8.0** 校验。插件 ID 为 `paseo-director`。

### 安装

在目标主机的 Paseo **Settings → Plugins** 开启插件，并确保运行 daemon 的用户有本仓库的 GitHub SSH 读取权限，然后执行：

```bash
paseo plugin add lalaze/paseo-plugins --path director
paseo plugin ls paseo-director --json
```

SSH 源：

```bash
paseo plugin install git@github.com:lalaze/paseo-plugins.git:director --ref main
```

`--path director` 或 `:director` 指定本多插件仓库中的插件子目录。安装会自动运行锁定依赖的 `npm ci --include=dev --ignore-scripts` 和类型检查，再由 Paseo 编译加载。确认状态为 `running` 后，在已有工作区发送 `/director`，打开 **协作设置** 保存 AI 分工。

### 更新

GitHub 源安装：

```bash
paseo plugin update paseo-director
paseo plugin ls paseo-director --json
```

更新会获取 `main` 的新提交并重新加载插件，无需重启整个 daemon。GitHub 同步的是插件代码，AI 登录信息、团队配置和任务记录保留在各自主机。建议在没有进行中的协作任务时更新。

本地目录安装不能使用 `paseo plugin update`。覆盖源码后：

```bash
npm ci --include=dev --ignore-scripts
npm run check
paseo plugin reload paseo-director
paseo plugin ls paseo-director --json
```

如果之前通过本地目录或旧仓库 `paseo-sub-agnet` 安装，请先卸载再从本仓库安装：

```bash
paseo plugin remove paseo-director
paseo plugin add lalaze/paseo-plugins --path director
```

完整切换步骤见 [INSTALL.md](./INSTALL.md#从目录安装切换到-github)。

### 卸载

```bash
paseo plugin remove paseo-director
```

Paseo 0.8.0 的移除操作不会删除 Director 数据目录、源码目录或工作区代码。同一 daemon 重新安装后，会继续使用 `$PASEO_HOME/director`（或 `PASEO_DIRECTOR_DATA_DIR`）里已保存的团队配置和任务记录。

安装、更新或重载失败时查看：

```bash
paseo plugin logs paseo-director
```

### 本地目录开发

如果已经克隆仓库，在 `director` 目录运行：

```bash
npm ci --include=dev --ignore-scripts
npm run check
paseo plugin install "$PWD"
paseo plugin ls paseo-director --json
```

原生插件需要主机已启用 Paseo 插件功能。插件在该主机执行本地代码。开发修改后执行上面的 `reload` 命令。

`paseo plugin install` 会记录目录路径。移动本仓库后，需要重新安装从该路径装过的插件。`npm run build` 优先使用已安装 Paseo CLI 中的官方编译器，验证宿主前后端边界并输出 `dist/`。没有 CLI 编译器时使用 esbuild，正式安装时再由 Paseo 校验。可通过 `PASEO_COMPILER` 指定官方 `compiler.js` 路径。

本机安装后的只读冒烟检查：

```bash
node --import tsx scripts/smoke.mjs
```

该检查只读取插件状态、RPC 和 provider 目录，不创建 AI 会话。

## 第一版实现范围

- 用户决定角色；任务指定优先于类型指定，再使用默认执行者。只有开启相应选项，设计 AI 才能从已配置列表选择执行者。
- 结构化计划与依赖校验、串行执行、按配置自动交给审核会话、最终集成审核。
- 支持结构化 JSON 回复和 HTTP MCP 工具两种交接方式。默认兼容模式；MCP 模式要求所选 AI 支持 HTTP MCP。流式回复按消息边界拼接，不在分片间插入换行；若旧任务因该问题停住，点击「我已检查，重试此步骤」会优先读取已有有效结果，保留总纲确认设置。
- MCP 工具：`submit_plan`、`dispatch_task`、`get_run_status`、`submit_review`、`submit_result`。按角色和运行范围授权；每次提交必须带当前步骤 ID。
- Git 快照包含未提交和未跟踪的非忽略源文件，使用临时索引，不修改用户暂存区。审核绑定快照版本；缺少审核证据或版本变化均不能通过。用户指定的额外检查失败时也不能通过；未指定检查会明确记录为未配置，由审核 AI 自行验证。
- 默认每项任务最多返工 2 次，总调用上限 40 次，总任务时限 4 小时。任务和下游依赖的验收会在返工时失效。
- 暂停后续派发、继续、取消、检查后重试。暂停或受阻时可修改完整需求，停止当前轮次后重新设计；已有代码保留，旧审核失效。
- SQLite 检查点、会话和消息标识、启动后周期核对；发送结果不明确时停止自动重发，避免重复执行修改。
- 客户端断开后，daemon 和插件后台仍运行即可继续。插件重载时自动派发短暂停止，恢复后核对已有会话。已启动 AI 的生命周期由 Paseo 管理。

## 运行文件

默认目录为 `$PASEO_HOME/director`，未设置 `PASEO_HOME` 时使用 `~/.paseo/director`：

```text
director/
  director.sqlite          # 角色配置、任务、步骤和检查点
  worktrees/<run-id>/       # 独立工作区模式的任务代码；同工作区模式使用原目录
  artifacts/<run-id>/       # 固定版本的 diff 和原始检查日志
```

SQLite 中包含 MCP 访问令牌，不应提交或分享数据库。界面与运行 RPC 不返回令牌。MCP 只监听本机回环地址，随机选择的端口会持久化并在重载时复用。

可选环境变量，设置在 **Paseo daemon 的启动环境**中：

| 变量 | 用途 |
| --- | --- |
| `PASEO_DIRECTOR_DATA_DIR` | 覆盖 Director 数据目录 |
| `PASEO_DIRECTOR_URL` | 覆盖本机 daemon WebSocket 地址 |
| `PASEO_DIRECTOR_PASSWORD` | 覆盖连接密码；否则使用 `PASEO_PASSWORD` 或 daemon 配置 |
| `PASEO_DIRECTOR_MCP_PORT` | 指定本机 MCP 端口 |

默认连接读取 daemon 的 `PASEO_HOME/config.json` 中 `daemon.listen`。非标准监听环境需设置 `PASEO_DIRECTOR_URL`；插件不会改写 daemon 配置。同一数据目录只允许一个 Director 后台实例。

## 实现与验证说明

任务状态机在 `server/engine.ts`，Paseo 接入集中在 `server/paseo.ts`。0.8.0 公共 SDK 尚未提供 agent handle 的取消方法，因此仅取消操作使用已固定版本的底层 `DaemonClient.cancelAgent`；其余会话管理使用 SDK facade。

自动测试使用模拟 AI，覆盖完整闭环、返工、故障恢复、权限、重复提交和取消；Git 测试操作临时真实仓库，MCP 测试使用真实本机 HTTP 传输。网络受限的测试环境需要允许回环连接。

第一版创建专属设计 AI 会话，暂不接管用户已有会话；运行中的 AI 配置采用启动快照，修改全局角色配置只影响后续新任务。会话失效、指令是否已执行不明确、超预算等情况会进入“需要处理”，经用户检查后才重试。跨 daemon 调度、并行子任务、自动合并和配置备用 AI 不属于此版本。

任务修改范围通过任务单和提示词约束，worktree 提供代码隔离，不是权限沙箱。文件访问和命令执行权限由所选 provider 的实际模式决定。
