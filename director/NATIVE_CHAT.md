# 原生协作对话实现

## 数据与边界

`conversations` 表独立保存会话生命周期、主 Agent、任务绑定、通知发送记录及用户操作收据。空白会话不创建 Run 或成果分支。Run 的 `chat` 字段标记新协议，缺省保持旧协议；迁移标记暂缓调度，绑定完成后旧操作按其原有 agentId 继续。

新建主 Agent 使用固定聊天系统指令和会话范围 MCP 令牌。原地接管保留原会话 ID、模型、权限、标题与历史，在当前会话加入协作说明，通过仅本机可读的 Node.js 桥接调用相同的协作工具；不修改原会话系统指令，不依赖宿主热更新 MCP。`get_conversation_status` 返回当前任务、主 Agent 所属操作的完整上下文、最新用户消息标识及待确认版本。`start_task` 延迟创建成果分支；`submit_operation` 只接受主 Agent 当前负责的设计或审核结果；`control_task` 复用状态机控制并记录幂等收据。执行者和审核者的令牌不提供聊天控制工具。

主对话可以从状态工具直接读取准备中的设计或审核操作并提交工具结果，不必结束当前聊天再等待另一条提示。主对话的普通后续消息不使已有工具提交失效；执行者及旧会话继续遵守原来的消息边界校验。聊天文字不会被解析成执行结果。

## 用户确认

后台只接受最新真实用户消息的 ID。所有后台操作及通知的消息 ID 都被排除在用户指令之外。批准必须位于当前确认通知之后，正文完整匹配明确批准语句，并绑定当前方案或成果键。引用、代码块、含糊回复及助手消息不能批准。最终验收再次核验实际代码快照。

用户指令通过会话收据以及 Run 内的原子收据避免重复执行。需求修改先暂停派发，异步停止执行者并核对状态；未完成的停止动作持久化后继续核对，旧步骤的工具提交不能改变新版本。

## 通知与入口

后台通知只在主 Agent 空闲、且没有正在交接给主 Agent 的操作时发送。未发送的连续进度合并为最新状态。发送前保存 `sending`，断线后查询原消息 ID；无法确定送达时不盲目重发，用户可显式重新同步。已发送通知保留，以核验确认时序。

客户端保留宿主设置屏幕、工作区设置按钮、迁移说明及恢复错误。`/director` 和「在当前对话启用协作」使用 agent 命令上下文，将当前 agentId 传给服务端；首次设置保存后恢复该会话的接管请求。「新建协作对话」保留显式创建入口。新主 Agent 由宿主自动加入工作区标签栏，插件命令不强制切换焦点。子会话使用宿主原生 subagent 入口，插件不再注册输入框胶囊或子任务列表。完整任务状态与暂停、继续、停止操作由主对话的 MCP 工具提供；原生停止按钮只停止当前聊天轮次。

插件时间线追加必须通过宿主回调提供的 `context.paseo`；普通 daemon 连接只用于会话查询、创建、发送及取消。没有宿主插件连接时保留待恢复状态。

## 迁移与恢复

迁移保留旧 Run 的 ID、目标、阶段、任务、成果、审核和操作 ID。新主 Agent 继承持久化任务上下文，旧会话不被覆盖；新执行会话建立新父子关系，已有子会话保留在原工作区的会话历史中。迁移失败不重复创建主会话或重新执行旧任务。

创建请求先存会话；Agent 创建失败或回执丢失后按标签寻找原会话。Run 已创建但会话关联尚未提交的故障通过 `chat.conversationId` 恢复关联。配置和草稿格式不变。

## 验证

自动测试覆盖空白会话、完整聊天闭环、主会话追加消息、明确验收和模糊／伪造批准、角色工具隔离、旧状态迁移、创建中断、通知回执丢失及 MCP 不可用。另须在实际宿主验证原生输入、原生子会话入口、子会话跳转、设置与窄屏布局。

## 原地接管与可靠性

`Conversation.takeover` 持久化接管说明和待发送命令。服务端先验证原会话仍在当前工作区且不是执行或审核子会话，再绑定会话并添加协作标签。当前模型以单独的主角色快照加入任务配置，不覆盖共享的执行／审核配置。命令重试保留请求 ID，不因切换标签误用另一个会话的请求。

正在运行或等待权限的会话不被停止；消息在空闲时发送。发送前保存 sending，重载后按消息 ID 核验；送达情况不明确时等待显式重新同步，不自动重发。原对话丢失时禁止自动新建替代会话。接管之前的历史仍可阅读，但不能作为新任务控制的 sourceMessageId；空白接管消息也不计为用户实施指令。

`server/bridge.ts` 生成仅当前系统用户可读的脚本，命令参数只有工具名，JSON 参数走标准输入；会话令牌不会出现在聊天、RPC 摘要或命令行参数里。脚本通过系统临时目录的私有文件队列发送请求，不需要 Agent 的网络权限。服务端与 HTTP MCP 共用参数校验、工具权限、消息核验及幂等控制；写入响应收据后删除请求，收到响应的脚本清理收据，重载可核对未完成请求。`get_conversation_status` 成功调用后才记录工具握手。

执行操作提示和 `get_run_status` 也提供持久化的 `workflowEvidence.planApproval`。原地接管的主对话记录用户批准后，执行 Agent 可以直接核对批准状态与时间，避免因子会话看不到主对话历史而再次要求批准。
