# paseo-todo

Sidebar queue for tasks that each run in their own git worktree. A person presses **Accept and ask agent to merge** to send a merge command to the session that produced the result. That agent handles the local merge, conflicts, and validation. Closing the sidebar does not stop the queue or merge monitoring.

The page is a board modelled on [codeg](https://github.com/xintaofei/codeg)'s To-dos: **To do**, **In progress**, **Needs you** and **Done** columns, a card per task with one next action (Start, Review, Retry, Open session), a detail sheet with the prompt, the review panel, git details and the diff, and a **New task** dialog that can add a task or add and start it. A single-agent task can choose a thinking level when its model supports one; **Provider default** leaves it to the provider. Changing the model clears the previous thinking level. **Start** runs that one draft; **Start all** queues every draft shown.

The sidebar page gathers tasks from every connected host that has this plugin installed: each card shows its machine and project, **All machines** narrows the board to one host, actions and **Open session** go to the task's own host, and **New task** asks which machine to run on. Each host keeps its own queue, worktrees and data directory; nothing is copied between machines. A host appears once its copy of the plugin is updated to this version.

Inside a workspace, the **Tasks** panel sits next to Files and Changes in the explorer (or run **Tasks for this project** from the command center). It shows the same columns stacked, only for that project, and adds new tasks to the project root. The sidebar page still shows every repository. Plugin ID: `paseo-todo`. It needs a Paseo daemon from 0.10 up to, but not including, 0.12.

## Collaboration

Collaboration is chosen in the **New task** dialog with **Enable collaboration**. Off and "never saved" both leave a new task as a single agent. **Plan first** adds planning before implementation; it is off for the first task. Enabling it exposes **Require plan approval**, also off by default. Select execution and review models: the reviewer owns the main conversation, performs optional planning, reviews the separate execution session, and receives the merge request after acceptance. Thinking levels and permissions belong to each selected role. **Provider default** leaves thinking to the provider. Changing a model clears the previous thinking level. The collapsed **Advanced settings** row shows the rework limit and time budget. Adding a task remembers that choice in this browser (`localStorage`, key `paseo-todo.collaboration-defaults.v1`) so the next new task on the same machine starts there. It is not written to the host's collaboration settings.

Reviewer-led tasks require the host's `collaborationUnified` capability; an older host shows an update message before dispatch. Wire modes remain `full` (planning) and `execute_review` (direct execution). Existing started tasks retain their saved main session and role configuration; editing an unstarted task or using remembered defaults adopts the two-role form without changing existing task records. Current hosts use their global role prompts even when a conversation supplies its own settings. Explicit task prompts must match the host prompts; blank fields use the host defaults. The plugin checks this before sending the goal and reports a mismatch instead of silently ignoring a task prompt. It never writes global prompts to work around this restriction.

**New task** starts from the choice remembered for that machine. Its collaboration controls sit in that same dialog, and **Add to To do** stores the snapshot on the task. Tasks already in the list are not changed. On a draft that has not started, **Edit task** on the card opens the task editor with its saved title, prompt, target branch, execution model, thinking level, and collaboration settings. Saving updates that same task and leaves it in **To do**. Its machine and project stay fixed. Editing does not change the defaults for new tasks. You can also open the card and press **Edit** under Collaboration. **Cancel** discards the edit. A failed save keeps what you typed. **Start** and **Start all** will not drop an unsaved edit: that task, and **Start all** for its machine, stay put until you save or cancel. After the task starts, the snapshot is read-only. Switching machines reloads that machine's capabilities and models.

A collaboration task opens its own worktree first, then enables collaboration in that directory before the goal is sent. A host that cannot run collaboration shows the error and does not fall back to a normal agent. The main agent's turn ending does not finish the collaboration. Plan approval and the collaboration result are accepted in the session (**Open session**); this page does not approve or accept them for you. While the session acceptance is still pending, the sheet asks you to open the session and will not merge. After the session is accepted, **Accept and ask agent to merge** checks the review binding and sends the merge instruction to that collaboration's main session.

For collaboration, the plugin reads host status again immediately before dispatch and addresses the current main conversation; a missing or disabled main session is refused. The merge instruction includes the repository, task worktree, task branch, target branch, and accepted commit. It asks the original agent to merge the latest target into the task branch, resolve conflicts using its existing context, run relevant validation, and merge back into the target. It preserves both histories, protects uncommitted target changes, and does not authorize pushing. The plugin does not run the merge itself. **Open session** shows the merge progress and any permission requests. A completed turn alone is not proof: the plugin checks that the accepted result is in the task branch, the full task branch and the accepted target history are in the target branch, and both worktrees are clean before marking **Merged** and cleaning up. If this cannot be confirmed, the worktree, branch, and session remain for investigation. Continuing the merge in the original session resumes monitoring.

Collaboration status is checked in the background while the plugin runs, including when this page is closed. Retrying a blocked run queues that same run behind other tasks in its repository; other retries and follow-ups stop the old run before opening a new session. Once a review binding has become stale, polling the same completed run will not capture later local edits as a newly reviewed result.

`install-all.sh` does not install this plugin. Add it on its own:

```bash
paseo plugin add git:lalaze/paseo-plugins --path todo
```

From a local checkout, `cd todo && npm ci && npm run build` typechecks and writes `dist/`. The daemon loads the built plugin; this package does not restart it.

The queue connects with `PASEO_TODO_URL` and `PASEO_TODO_PASSWORD` when those are set, otherwise the daemon address and password in `~/.paseo/config.json`. Tasks and the single-process lock live in `PASEO_TODO_DATA_DIR` or `$PASEO_HOME/paseo-todo` (default `~/.paseo/paseo-todo`).

## Limits

- Queue and Git locks use the canonical shared Git directory, so linked worktrees of the same repository share one execution queue and merge exclusion. Task working paths are preserved, including in existing archives. If repository identity cannot be resolved before dispatch, the task records a preparation failure and can be retried after the path becomes available; other repositories keep running.
- Deletion first confirms the run and session stopped, then archives sessions, removes the worktree, and deletes the task branch. A failed step stops deletion, keeps the task record and shows the error; resolve it and retry **Delete**. For merged tasks, saved successful cleanup steps are skipped. A fully cleaned task can be removed from the board even when its old daemon session or repository is unavailable. Only complete cleanup removes the record.

- No dependency graph. Nothing is pushed.
- After a verified merge the task cleans up after itself, in order: it confirms the original agent is idle, archives the task's sessions and the workspace opened on its worktree, removes the worktree with `git worktree remove` (no `--force`, so an uncommitted or untracked file stops it; ignored files such as `node_modules` go with the worktree), then deletes the `paseo-todo/…` branch only if its tip is the verified post-merge tip, that commit is in the target branch, and no worktree has it checked out. A failed step is shown on the task with a **Retry cleanup** button; the merge itself stands. Your own checkout's branch is never switched.
- The plugin will not merge because a turn ended, a permission was resolved, or the agent said it was done. An agent that can run a shell can still run git itself.
- Accept sends the review binding shown on that screen. A stale page is rejected and does not replace the saved binding.
- A new turn on the producing session blocks acceptance while it is running, waiting for permission, or cannot be inspected. When it ends, a chat-only turn keeps the binding if the result, clean worktree and target HEAD still match; changed files or refs invalidate it.
- Development retries and sent-back rounds first stop and inspect the previous session, including single-agent sessions resumed after review. A busy or uninspectable session prevents a replacement from starting. Once stopped, these rounds get a new agent. Merging reuses the producing session; a separate saved message ID and turn binding keep old completions from finishing the merge.
- A started collaboration has **Stop collaboration** on its card and in its detail sheet. It stops the host run and its current main session, including a replacement created by resync, and saves the confirmed host state. If the plugin cannot prove the agents stopped, the task stays in `canceling` and keeps the repository queue blocked; **Retry stop** tries again without dispatching work. An inspect failure is not treated as stopped.
- Shutdown waits for an in-flight prepare, capture, merge dispatch/verification, or state write before releasing the data directory. It does not start another task after that. A saved merge command is never resent on restart: monitoring reattaches to the original session and checks Git when it is idle.
- The data directory lock is the `state.lock` directory. An empty file, unreadable owner record, or dead pid is left in place; delete it by hand only when no paseo-todo process is using the directory.
- A conflict is handled by the original agent. The instruction requires it to stop for dirty target worktrees or pre-existing Git operations instead of overwriting user changes. The plugin does not `reset`, `clean`, or `merge --abort`.
- Two git processes can still race around the final ref update. The plugin checks the ref again and records a failure instead of rolling a user commit backward.
- If the daemon cannot be reached, sessions are treated as unknown, not stopped: accept is refused, a cancel stays pending, and recovery leaves the task as it was. The plugin reconnects on the next call.
- A task sent back for changes runs in a new session that gets the original prompt plus the requested change, in the same worktree.
- Restart never resends a saved operation. If success cannot be proven, the task stays needs-check or failed.
